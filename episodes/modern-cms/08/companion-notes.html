Companion reference

An admin-interface change may be application configuration. Export it, inspect it, and move it through the tested deployment workflow.

Translate the terminology

Episode 8 reference
TermUseful mental model
composer.json / composer.lockRequested package constraints / resolved dependency versions.
Composer install / updateInstall the locked set / resolve allowed versions and revise the lock.
Active configurationThe configuration currently used by the site, normally stored in its database.
Config export / importWrite configuration to synchronization files / synchronize active configuration from that set.
OverrideAn effective runtime value that may differ from exported stored configuration.
Drush deployA coordinated Drupal deployment command; inspect the installed version and project procedure.

What moves by which mechanism?

Common deployment boundaries
ItemTypical treatment
Field definitions, Views, display settingsReviewed configuration export/import.
Events, people, taxonomy termsContent storage, migration, or deliberate content workflows.
Core, contrib, custom codeVersion control, locked dependencies, and tested release artifacts.
Uploaded filesManaged storage, backup, and deliberate synchronization.
SecretsProtected environment or secret-management process.

The commands above illustrate an existing-site workflow. They are not an all-purpose production runbook.

Try the reasoning

  1. Confirm the target environment before any modifying command.
  2. Review all configuration changes, including deletions and module dependencies.
  3. Do not use a stale development database to replace current production content.
  4. Test the complete editorial path and recovery plan on staging.
  5. Account separately for code, configuration, content, files, and secrets.
