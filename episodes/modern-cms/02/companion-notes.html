Companion reference

WordPress combines a publishing-oriented data model, extension hooks, and theme conventions with a large ecosystem. Evaluate the actual requirement rather than ranking CMS identities.

Translate the terminology

Episode 2 reference
TermUseful mental model
Post typeA registered kind of content record; a custom type does not automatically get a new database table.
Taxonomy / termA classification system / one value in that system.
Theme / templatePresentation package / a selected structure for output.
PluginA package of WordPress functionality.
ActionAn extension point that invokes behavior.
FilterAn extension point that passes a value through callbacks which return a value.
BlockAn editable content or layout unit; static and dynamic blocks have different rendering lifecycles.

Example boundaries

The complete PHP plugin in the transcript registers a basic public event type. It does not implement scheduling, bookings, custom date fields, or department-specific authorization. Its labels are English demonstration strings; production localization is additional work.

Try the reasoning

  1. Activate the example plugin only in a development site and verify Events appears.
  2. Review the default post capabilities before using the type with real editorial roles.
  3. Create an event, inspect its public output, and check API access.
  4. Keep content-type registration in a plugin when it must survive theme changes.
