Entity type → bundle → entity → fields. Use the general API model without assuming one object equals one database row or every bundle equals a PHP subclass.

Episode 3 reference
TermUseful mental model
Entity typeKind of managed Drupal data object, with declared capabilities and handlers.
BundleConfigured subtype of an entity type; not every entity type has multiple bundles.
EntityAn individual managed data object.
FieldStructured property/data with a type, storage, validation, and presentation options.
Entity referenceRelationship to another entity; ordinary references do not automatically pin a target revision.
TaxonomyClassification using vocabularies and terms.
ViewQuery and presentation configuration.
View modeNamed presentation context for rendering an entity.
ModuleExtension/functionality package.
ThemePresentation layer.
ServiceReusable functionality represented by an object managed by the service container.
HookAn extension point invoked by Drupal.
Render arrayStructured description of output Drupal renders later, with metadata.
ConfigurationSite/application definitions and settings that can be managed and deployed.
ContribCommunity-provided projects, each with its own support and compatibility.
DrushDrupal command-line tooling.

Two distinctions that prevent migrations from going wrong

A public Person profile is not automatically a login account. A media entity is not synonymous with the file bytes it represents. Model their lifecycles and access separately.
