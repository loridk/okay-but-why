Episode guide

Next.js Series

Start at Episode 1 or jump directly to any Next.js topic. Each page includes the audio, transcript, and code cards.

  • Episode 1: Wait, React Needs a Framework Now? Why React alone leaves routing, rendering, data loading, backend work, optimization, and deployment decisions to you — and why Next.js exists to make those choices part of a framework.
  • Episode 2: The Folder That Controls Reality How the App Router turns folders and files into routes, layouts, pages, dynamic segments, loading states, error boundaries, and not-found behavior.
  • Episode 3: React Runs WHERE? Server Components versus Client Components, where code executes, what gets sent to the browser, hydration, interactivity, secrets, and the meaning of "use client."
  • Episode 4: SSR, SSG, CSR and Please Stop Inventing Acronyms Server rendering, static generation, client rendering, streaming, hydration, and why modern Next.js can mix rendering strategies instead of choosing one for the entire application.
  • Episode 5: Why Am I Fetching My Own Data Over HTTP? Fetching data directly in Server Components, parallel versus sequential requests, loading and error states, database access, and when an internal API call is unnecessary.
  • Episode 6: Caching: Why Is My Website Lying to Me? Why caching exists, what can become stale, revalidation, invalidation, dynamic data, request-time rendering, and reasoning about freshness instead of memorizing cache incantations.
  • Episode 7: Did We Just Put the Backend in the Component? Server Actions, forms, mutations, validation, authentication and authorization, progressive enhancement, revalidation, and why server-side code still needs normal security boundaries.
  • Episode 8: Oh, So There IS a Backend Route Handlers, HTTP methods, request and response objects, webhooks, external consumers, API endpoints, validation, authentication, and when a real HTTP boundary makes sense.
  • Episode 9: Next.js Ate My Web Stack How routing, rendering, server code, APIs, caching, middleware, assets, metadata, and deployment fit together — and what Next.js still does not replace.
  • Episode 10: Do I Actually Need This Shit? When Next.js earns its complexity, when React without Next.js is enough, when a traditional server-rendered application is simpler, and when you probably don't need React at all.
Okay, But Why? — Tech concepts without the ceremonial fog.
