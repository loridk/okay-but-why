# Okay, But Why? — TypeScript Series

Status: Draft production plan

1. **JavaScript With a Complicated Little Hat** — What TypeScript is, why it exists, what it catches, and what it cannot do.
2. **JavaScript Already Has Types, So What the Hell?** — Runtime types, `typeof`, inference, annotations, primitives, arrays, objects, and functions.
3. **It Can Be a String or a Number. Now What?** — Unions, nullability, optional values, narrowing, type guards, and control-flow analysis.
4. **Please Describe Your Object** — Object shapes, type aliases, interfaces, optional and readonly properties, arrays, and tuples.
5. **Functions Have Boundaries** — Parameter and return types, optional/default/rest parameters, callbacks, `void`, and function contracts.
6. **The Reusable Type Machine** — Generics, type parameters, inference, constraints, and when generics become decorative architecture.
7. **The Escape Hatches Department** — `any`, `unknown`, `never`, assertions, exhaustive checks, and why lying to the compiler remains lying.
8. **Who Invited the Compiler?** — `tsc`, `tsconfig.json`, `strict`, `target`, modules, `noEmit`, source versus output, and the surrounding toolchain.
9. **Put It in a Real Project** — Gradual migration, third-party types, declaration files, API boundaries, React/TSX, and deciding where TypeScript earns its keep.

The series deliberately teaches runtime validation as a boundary, not as a TypeScript feature. React remains its own future series; Episode 9 only explains the TypeScript/TSX connection needed to enter that series without mystery.
