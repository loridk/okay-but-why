Keyboard quick reference

These are common desktop web patterns, not universal commands for every component. Browser, operating-system, and assistive-technology settings can affect key handling.

Tab / Shift+Tab
Move forward/backward through the sequential focus order. Composite widgets may have one entry point rather than a stop on every item.
Enter
Activate a focused link or button. Form submission behavior also depends on the form and focused control.
Space
Activate a native button or toggle a checkbox; on an ordinary link or document it typically scrolls rather than activates.
Escape
Commonly dismiss a dialog or popup when that pattern supports dismissal. A custom component must implement its intended behavior.
Arrow keys
Navigate within appropriate controls such as radio groups, tabs, and menus. Use the component's established pattern; do not intercept arrows across the whole page.

Focus terms and tabindex

  • Keyboard focus: the current input target; not necessarily the screen reader's reading cursor.
  • Focus indicator: the visible marker showing that target.
  • Focus order: the meaningful route between targets.
  • Programmatic focus: code moving focus for a justified workflow transition.
  • tabindex="0": participates in normal sequential navigation; supplies neither role nor activation.
  • tabindex="-1": generally outside sequential navigation but available as a programmatic focus destination; not disabled or hidden.
  • Positive tabindex: creates a competing priority order; fix document structure instead wherever possible.

Dialog and dynamic-interface checks

  1. Opening a modal moves focus to an appropriate place inside it.
  2. Focus stays within the active modal while it is open; background interaction is unavailable.
  3. A clear keyboard-operable close control and appropriate Escape behavior provide an exit.
  4. Closing returns focus to the opener or a logical next destination if it no longer exists.
  5. Names and instructions are available. The close control survives zoom and small viewports.
  6. Routine asynchronous updates do not steal focus.
  7. Client-side navigation updates context deliberately: title, structure, and an appropriate focus strategy.

Native dialog.showModal() provides important modal behavior; show() and a bare open attribute are not equivalent. Custom role="dialog" and aria-modal="true" do not implement focus handling or inertness.

One useful keyboard journey

Reload → activate skip link → complete fields → open/close delivery options → trigger errors → correct errors → open/close address dialog → complete a simulated order. Repeat relevant navigation backward. Record the exact key, focus location, expected result, actual result, and environment for failures.
