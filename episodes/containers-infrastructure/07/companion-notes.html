Companion reference

A push transfers source history. A configured pipeline can check it, build a known artifact, and deploy that artifact to an actual runtime environment.

Key terms

CI
Frequent integration supported by automated checks.
Continuous delivery
A process that keeps changes releasable, commonly with an explicit production release decision.
Continuous deployment
Automatically releases qualifying changes to production.
Runner / registry / deployment target
Executes pipeline jobs / stores images / runs the released application.

Release path

Each arrow represents a configured action; Git itself does not deploy software.

Release questions

  • Which source revision and image digest are deployed?
  • What did the checks actually verify?
  • Which identity can release, and what can it access?
  • How do we detect failure and preserve useful logs?
  • Can old and new code coexist with database changes?
  • What recovery action has been tested?

Untrusted workflow code must not inherit production secrets. Rolling back an image does not reverse database changes.
