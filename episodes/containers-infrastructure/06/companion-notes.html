Companion reference

Compose describes related services together. Startup ordering, readiness, application behavior, and production operations remain distinct concerns.

Key terms

Compose service
A named component with an image/build definition and runtime settings.
YAML
A data notation whose nesting uses indentation; Compose defines the meaning of these keys.
Network
Provides a communication context; connected services can discover one another by service name.
DDEV / Lando
Development tools that add conventions, recipes, routing, and workflows over container infrastructure.

Conceptual three-service arrangement

Browser → frontend server/proxy → API → database. The frontend server and API share edge; the API and database share backend. The database has a named volume.

Illustrative, incomplete Compose YAML; do not run as supplied. Frontend and API images are fictional. Frontend proxy routing, API behavior, database credentials, secret delivery, health checks, and startup dependencies are deliberately omitted. The frontend must actually be configured to proxy its API path to api:3000. PostgreSQL 17 is selected to make this example’s data-directory path explicit; check the image documentation when changing major versions.

Commands in a real configured project

A configured service_healthy dependency condition can wait for readiness at initial startup. Runtime failures still require application retries and reconnection. Do not add volume-removal cleanup flags without understanding which data they delete.
