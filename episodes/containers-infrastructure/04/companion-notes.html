Companion reference

Dockerfile describes construction. Image is the packaged result. Container is an instance created from that image.

Key terms

Base image
Starting filesystem content and configuration for a build stage.
Layer
Stored filesystem changes assembled into an image; metadata instructions are not all filesystem layers.
Registry
Stores and distributes images; Docker Hub is one example.
Tag / digest
A potentially movable name / a content identifier. Pinning needs a deliberate update policy.

Lifecycle

A build produces an image. Push distributes it through a registry; pull obtains it elsewhere. Multiple containers can be created from that same image.

Small annotated example

Illustrative Dockerfile only. Assumes a fictional, plain JavaScript Node API with package.json, package-lock.json, and server.js, no compilation step, and a server that listens on an appropriate container interface. These application files are intentionally not supplied. This is not a complete production configuration.

For a real project, explicitly include all required application files and build steps. Exclude secrets and unwanted files with .dockerignore; .gitignore does not control build context. Review base-image updates and record tested digests. Never add a secret then rely on a later layer to delete it.
