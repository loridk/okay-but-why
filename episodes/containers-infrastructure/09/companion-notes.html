Companion reference

Desired replicas: 3. Actual replicas: 2. Controllers work toward restoring the missing replica; successful scheduling, startup, and readiness are separate steps.

Key terms

Cluster / node
The coordinated Kubernetes system / a physical or virtual machine that can run Pods.
Pod / container
Scheduled unit sharing a networking context / application process environment within it.
Deployment / ReplicaSet
Manages a replicated workload and rollout / maintains its set of Pods.
Service
A stable network abstraction for changing endpoints; does not create the application Pods.

Read the hierarchy

The cluster includes a control plane and nodes. A node runs Pods, and each Pod contains one or more containers. The diagram is conceptual; it does not imply a production-ready placement strategy.

Three probes

  • Startup: allows initialization before liveness/readiness probing takes over.
  • Readiness: controls eligibility for normal Service traffic; failure does not itself restart the container.
  • Liveness: repeated failure can trigger a container restart.

Containers in one Pod share localhost. Different Pods do not. A Deployment progress deadline reports a stalled rollout; automatic rollback requires additional action or automation.
